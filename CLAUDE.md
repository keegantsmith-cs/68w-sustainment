# 68W Sustainment — project guide for Claude

A static web app (no build step) for US Army 68W Combat Medic sustainment training. It's hosted publicly on GitHub Pages.

## Layout
- `js/data.js`: ALL content (resources, documents, textbook chapters). Most changes happen here.
- `js/app.js`: hash router and views (home, resource, doc, saved, downloads, search, profile).
- `js/art.js`: placeholder SVG artwork. `css/styles.css`: theme; the phone layout is under `@media (max-width: 640px)`.
- `sw.js`: offline cache. **Bump `VERSION` whenever app files change.**
- `js/ictl.js`: GENERATED from `docs/ictl/*.pdf` by `python3 scripts/build_ictl.py`. Never hand-edit it; re-run the script.
- `js/cpg.js` and `js/adtmc.js`: GENERATED by `scripts/build_cpg.py` and `scripts/build_adtmc.py` from PDFs that are NOT committed. ADTMC is index-only: never add its protocol text or doses to the site.
- `js/drugref.js`: GENERATED by `scripts/build_drugref.py`. The reconciled drug reference (Rev 5 file, 18 Nov 2026) was approved by a medical authority on 19 Nov 2026 (user-confirmed), so its reconciled cards publish word for word. Cards marked not reconciled, and calcium gluconate (citation unconfirmed), stay dose-free; PCC antibiotic cards were not approved and stay index-only. The build checks every field against an independent extraction of its page and fails on dose-like text in any entry not approved for doses.
- `js/tccc.js`: GENERATED by `scripts/build_tccc.py` from `content/tccc/tccc-sections.json` (reviewed TCCC 01 May 2026 section summaries; same quote/number checks as the CPGs; source PDF not committed).
- `js/smog.js`: GENERATED by `scripts/build_smog.py`. SMOG FY27 (01 Oct 2026) INDEX only: written for Critical Care Flight Paramedics; requires unit medical-director endorsement.
- `js/fieldcare.js`: GENERATED by `scripts/build_fieldcare.py`. OUTLINES only of the Ranger Medic Handbook (2025) and the PFC Field Handbook (2025). Both are commercially copyrighted (Breakaway Media): never their text, never the PDFs, even if they are publicly available.
- **Source precedence (owner's direction, 20 Nov 2026): follow the most recent official guidance within scope.** For line-68W point-of-injury care that is TCCC 2026; SMOG FY27 governs en route/aeromedical care. Drug cards that conflict are dose-held until reconciled; disagreements go in the private review reports (`SOURCE_ISSUES_FOR_REVIEW.md`, `DRUG_CROSSCHECK_FOR_REVIEW.md`, both git-ignored).
- `content/cpg-summaries/cpg-<ID>.json`: reviewed CPG summaries. `build_cpg.py` checks every quote against its PDF page, rejects quotes that end mid-phrase, and rejects any number in key-point text that isn't in that point's quote. New summaries go content-curator → clinical-reviewer → fixes → build.
- `scripts/check.js`: validation. Run `node scripts/check.js` before every commit.

## Hard rules
1. The repository and site are PUBLIC. Never commit PDFs or Office files, copyrighted text, FOUO/CUI, OPSEC-sensitive details, or PII. `.gitignore` blocks `docs/**/*.pdf` etc. Restricted documents are linked with `url` to an access-controlled host.
   - Exception: ICTL PDFs in `docs/ictl/` are marked "Approved for public release; distribution is unlimited" and ARE committed. `scripts/check.js` fails if any tracked PDF lacks that statement.
2. Never invent clinical content (doses, protocols, task standards). Only use text from a source document the user provides, and cite it (title, edition, chapter and page).
3. Summaries and outlines (titles, chapter names, page numbers) are fine. Do not reproduce large passages of copyrighted textbook text.
4. Keep the look consistent with the mock-up: dark green, tan accents, uppercase tracking labels. Every change must work at desktop and iPhone widths.

## Run / test
- `python3 -m http.server 8000`, then open http://localhost:8000
- Playwright is available (`require('playwright')`) for screenshots at 1295x965 and with `devices['iPhone 13']`.

## Agent team (`.claude/agents/`)
| Agent | Use it to… |
|---|---|
| `content-curator` | Turn a source document (PDF, TOC, list) into `data.js` entries |
| `clinical-reviewer` | Review content for accuracy, citations, copyright, OPSEC and PII (read-only) |
| `ui-tester` | Test desktop and phone layouts, routes and console errors with screenshots |
| `release-manager` | Run pre-publish checks, bump the cache version, commit |

Typical flow when the user hands over a document: content-curator → clinical-reviewer → ui-tester → release-manager.
